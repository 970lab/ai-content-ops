# Start with one post

Finish this guide with **one complete local text draft** and a clear next action. No code, installation, account login, cover image or video is required. Use the same process for a media post later.

## 1. Open the package

Unzip the supplied review package (or the repository ZIP after release) and open `README.md`. Markdown files ending in `.md` are ordinary text: open them in your text editor if you have no Markdown viewer. Python is optional; skip every script and registry section for this exercise.

Keep this guide open. Create a private folder named `my-first-post`, with a subfolder named `sources`. Copy [first-post.md](../templates/first-post.md) into `my-first-post` and name that copy `draft.md`. This is the only working draft to maintain. You do not need a ledger or artifact IDs for one manual post.

## 2. Supply one source

Save the permitted facts as `my-first-post/sources/source-note.md`. Write what you did or want to explain, what you can show, what remains unknown, and the date/version if relevant. An author's own statement can support that author's reported experience; it does not prove all users will get the same result.

If you have no material yet, copy the bundled [fictional source note](../examples/first-post/source-note.md) and label the exercise fictional. Do not present the practice story as your experience. An [example completed draft](../examples/first-post/draft.md) is included for comparison after your attempt.

For a manual first post, the source you explicitly supply is enough to begin; no historical change checkpoint is required. Periodic automated discovery is a different mode, with its own [allowlist and checkpoint rules](../references/release-sequence.md).

## 3. Choose the smallest useful format

Choose **text only** for this first pass. Fill the first three sections of `draft.md`: reader question, your point of view, and supported statements/unknowns. For voice, write one or two sentences as you would say them, instead of trying to sound professional. One real sentence is enough to begin. Leave an unknown motive blank; label any helper-proposed angle as a suggestion awaiting your acceptance.

A text post needs a title, opening, body and ending. Cover, narration, shots, music and export checks are not applicable unless you choose them. A link that will display a preview card creates an actual visual check later; do not mark that card exempt merely because the post is mostly text.

## 4. Give your helper one request

Open [start-here-prompt.txt](../templates/start-here-prompt.txt). Paste that entire prompt into an AI tool you already use, followed by the **contents** of `draft.md` and `sources/source-note.md`. If file attachments are supported and authorized, attach those two files instead. Pasting a local pathname alone does not let a web chat read the file. Use only information you may share with that tool.

The prompt asks for output in your chosen language and one complete draft. Save output A (title and text) in section 4, B/C (claim checks and findings) in section 5, and D (next action) in section 6 of your existing `draft.md`; do not create another “final” file. A long claim review may live in `sources/fact-review.md`, referenced from section 5. Keep every required attachment inside `my-first-post`, never in a parent or sibling folder. You can also write the post yourself using the same fields.

## 5. Review the result yourself

Read the whole post aloud. For each sentence about an experience, result, time, cost or capability, ask which source supports it. Remove unsupported additions. Keep advice visibly phrased as advice, not as something the author already did. Check that the title's promise is actually delivered in the body.

Fill section 5 with what you changed and what is still unknown. If nothing is missing for a text draft, say so; do not invent a filming task. If the story truly depends on a missing visual demonstration, narrow the claim or choose the media route below.

## 6. Save and stop at the agreed boundary

Fill section 6: revision, date, next action, owner, and “local draft only; do not upload or publish.” Your first text draft is complete when it has readable title/body, traceable claims, review notes and a next action. It may still need author acceptance and destination checks. Leave platform URLs and metrics absent until they exist.

For a later revision, keep one current `draft.md`; preserve the prior revision in version history or an explicitly named history folder. Do not keep two competing current copies.

## Resume on another computer or in a new chat

Transfer the **whole** `my-first-post` folder using storage you already trust. Keep the `sources` folder beside the draft so relative references still resolve. Include any review attachments as well; a reference in the root `draft.md` beginning with `../` escapes this folder and will be missing if you transfer only this folder. Put required attachments inside the folder and update their references before transfer. On the receiving computer, open the actual draft and source files, check the revision and necessary assets, and confirm the copy opens correctly. Do not assume a visible filename means a completed sync. Pick one writable current copy before continuing; never edit two machines' copies concurrently without a deliberate merge process.

Give the new helper section 6 and the actual draft/source contents. Do not assume it has your prior chat, local files, accounts, fonts, voice profiles or tools. Reconnect any needed tools through their normal setup; this package does not synchronize credentials. Local folder-copy checks are not proof of real cross-device use.

## When you need images, audio or video

Keep the selected text. Add only the relevant media fields from the [advanced worksheet](../templates/content-worksheet.md): real assets, missing shots, rights and export review. Then follow [the complete workflow](creator-workflow.md) for actual production, destination preparation, authorized actions and receipts. You do not need the advanced worksheet to finish this first text draft.
